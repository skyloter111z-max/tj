## 1. 불변 설계 제약 (Invariants)

이 4개는 어떤 기능 요구사항보다 상위다. 하나라도 깨는 구현은 리젝트 대상이다.

> **INV-1 — 무수탁(No Custody).** 구독모아는 타인(파티원·방장)의 자금을 어떤 형태로도 보유·관리·이전하지 않는다. 선불 잔액, 포인트, 충전금, 예치금, 미지급 정산금을 **원장에 부채 계정으로 가질 수 없다.** 구독모아 계좌에 들어오는 돈은 **구독모아 자신의 상품 대금(수수료·멤버십)뿐**이다.
>
> **INV-2 — 조건부 집행(Condition-Gated Charge).** 분담금 결제는 **시간 경과로 발동하지 않는다.** 해당 주기의 이용 상태가 확인된 슬롯에 대해서만 결제가 집행된다. 미확인의 기본값은 **집행 보류**다.
>
> **INV-3 — 손실 한도 1주기(Capped Exposure).** 어떤 사고에서도 파티원 1인의 금전 손실 최대값은 **1개월 분담금**을 넘지 않는다. 선납을 받지 않음으로써 구조적으로 보장하며, 보상 적립금에 의존하지 않는다.
>
> **INV-4 — 자격증명 불출(Credential Containment).** OTT 자격증명은 구독모아 앱 내부를 벗어나지 않는다. 카카오톡·이메일·SMS·채팅 공지에 자격증명을 담는 경로는 **구현하지 않는다.**

### 1.1 비수탁과 지급 게이트의 충돌, 그리고 해법

이 재설계의 유일한 어려운 문제다.

- 지급 게이트의 본질은 "조건 미충족 시 방장에게 돈을 주지 않는다"다.
- 그런데 INV-1에 따르면 **구독모아는 보류할 돈을 쥘 수 없다.**

**해법: 보류의 대상을 "지급"에서 "청구"로 옮긴다.**

| | v1 | v2 |
|---|---|---|
| 돈의 위치 | 구독모아가 12개월분을 쥠 | 아직 파티원 카드에 있음 |
| 레버 | 지급을 보류 (= 수탁 필요) | **결제를 집행하지 않음 (= 수탁 불필요)** |
| 사고 시 노출액 | 최대 11개월분 | **최대 1개월분** |
| 법적 지위 | 미등록 전자금융업 | 통신판매중개업 |

**선납을 버린 대가로 수탁을 버린다.** 그리고 노출액이 11개월분에서 1개월분으로 줄어들기 때문에, 사기 방지 효과는 v1보다 **오히려 강해진다.** v1은 "먹튀당한 뒤 보상"이고 v2는 "먹튀당할 금액 자체가 1개월분"이다.

## 2. 자금 흐름 아키텍처

### 2.1 결제 경로 — 2건 분리 승인

```
                    ┌─────────────────────────────────────────┐
                    │  파티원 카드 (PG 빌링키 토큰)            │
                    └────────────┬────────────────────────────┘
                                 │  매 주기, 게이트 통과 시에만
            ┌────────────────────┴────────────────────┐
            │                                         │
      [거래 A] 분담금 (예 ₩2,400)              [거래 B] 수수료 ₩290
            │                                         │
            ▼                                         ▼
  ┌──────────────────────┐                  ┌──────────────────────┐
  │ 등록 PG — 하위몰      │                  │ 구독모아 계좌         │
  │ 분할정산              │                  │ (자기 상품 대금)      │
  │ 수취인: 방장          │                  │ ← INV-1 위반 아님     │
  └──────────┬───────────┘                  └──────────────────────┘
             │ PG 정산대금 별도관리
             │ (예치·신탁·지급보증보험)
             │ + 판매자 우선변제권
             ▼
  ┌──────────────────────┐
  │ 방장 계좌 (직접 입금) │
  └──────────────────────┘

  구독모아는 거래 A의 자금 흐름에 단 한 순간도 개입하지 않는다.
```

**거래 A와 B를 반드시 분리하는 이유.** 한 건으로 묶어 구독모아가 4,940원을 수취한 뒤 방장에게 재정산하면, 그것이 바로 **"하위 가맹점에 재정산"** 구조이고 PG 등록 대상이 된다. 분리 승인(또는 PG 분할정산 API로 거래 단위에서 수취인을 지정)해야 INV-1이 유지된다.

### 2.2 이 구조가 법적으로 서는 근거

2024 개정 전자금융거래법은 PG의 정의를 명확히 하면서 **"판매중개 등 다른 업무를 영위하는 과정에서 부수적으로 대가를 수수하고 정산을 대행하는 경우는 제외"** 한다고 규정했다. 구독모아는 통신판매중개를 본업으로 하며, 재정산은 등록 PG가 수행한다.

**동시에, 같은 개정법은 "오픈마켓 형태에서 결제를 받아 하위 가맹점에 재정산하려면 PG 등록을 해야 한다"고도 한다.** 이 둘은 긴장 관계이고, "부수적"의 범위가 쟁점이다. 따라서:

> ⚠️ **§9-1의 비조치의견서 신청은 선택이 아니라 Phase 1 착수 전 필수 선행 과제다.** 본 설계는 PG가 직접 방장에게 정산하므로 등록 대상이 아니라고 보지만, 이 판단은 금융당국 확인 전까지 **가설**이다.

### 2.3 부수 효과 — 방장의 무담보 채권자 지위가 소멸한다

v1에서 방장은 74,250원을 12개월간 구독모아에 외상으로 깔았고, 구독모아 파산 시 전액을 잃었으며 선불충전금 보호 대상도 아니었다.

v2에서 방장의 정산금은 **등록 PG가 보유**하고, 개정 전금법상 **정산대금 전액 외부관리(예치·신탁·지급보증보험) + 양도·압류·상계 금지 + 판매자 우선변제권**이 적용된다. 방장의 자금 안전성이 v1보다 **법적으로 한 단계 높아진다.** 이것은 §7의 공급측 설득 논거로 직접 쓸 수 있다.

### 2.4 PG 비용 귀속

| 항목 | 부담 주체 | 근거 |
|---|---|---|
| 거래 A(분담금) PG 수수료 ≈ 3.5% | **방장** (정산액에서 차감) | 표준 마켓플레이스 관행 |
| 거래 A 하위몰 분할정산 수수료 ≈ 100원 | **방장** (정산액에서 차감) | **거래 A에 부과되므로 거래 A 귀속** (v2.1 정정 — v2.0은 구독모아 부담으로 잡았으나 §5.3과 불일치했다) |
| 거래 B(수수료 290) PG 수수료 ≈ 10원 | **구독모아** | 자기 상품 대금 |

**방장 실수령 예시 (Duolingo 6인, 분담금 2,400원):** 2,400 - 84(PG 3.5%) - 100(분할정산) = **약 2,216원/파티원/월**.
가입 화면에 **실수령액을 금액으로 명시**한다 (§6.2).

## 3. 지급 게이트 (핵심 메커니즘)

### 3.1 2계층 구조

v1 비판에서 지적된 "게이트가 없다"를 고치되, **단순한 파티 단위 보류는 새로운 공격 경로를 만든다.** 파티원 1명이 확인 버튼을 누르지 않는 것만으로 파티 전체 결제를 멈출 수 있으면, 방장이 인질이 된다. 따라서 귀책 주체에 따라 계층을 분리한다.

| 계층 | 발동 사유 (귀책) | 효과 |
|---|---|---|
| **SLOT_HOLD** | 특정 파티원 귀책 (무응답, 규칙 위반 신고 접수) | **그 슬롯만** 결제 미집행 + 이용 중단. 나머지 파티원은 정상 결제, 방장은 정상 수령 |
| **PARTY_HOLD** | 방장 귀책 (비밀번호 변경, 계정 해지, 요금제 강등, 2인 이상 동일 신고) | **파티 전체** 결제 미집행. 전원 이용 확인 중단, 분쟁 절차 개시 |

### 3.2 주기 상태 기계

```
CYCLE_SCHEDULED
   │
   │ D-3  파티원 전원에게 이용 확인 요청 (푸시 + 알림톡)
   ▼
VERIFY_REQUESTED ──────────────────────────────────────┐
   │                                                    │
   │ 슬롯별 응답 수집 (D-3 ~ D-day)                      │
   │                                                    │
   ├─ "정상 이용 중" ACK ──→ SLOT_OK                     │
   ├─ "문제 신고" ────────→ SLOT_HOLD → DISPUTE_OPEN     │
   └─ 무응답 72h ─────────→ SLOT_HOLD (기본값)  ◀────────┘
   │
   │ D-day 집행 판정
   ▼
   ├─ 방장 귀책 신고 2건 이상 또는 헬스체크 실패
   │     → PARTY_HOLD : 전 슬롯 미집행, 분쟁 절차
   │
   └─ 그 외
         → SLOT_OK 슬롯만 CHARGE_AUTHORIZED
              ▼
         CHARGED ──→ SETTLED (PG → 방장)
              │
              └─ 결제 실패(한도·유효기간) → RETRY(최대 3회, 24h 간격)
                        └─ 3회 실패 → SLOT_SUSPENDED → 슬롯 회수 예고
```

### 3.3 무응답 대칭 처리 — 양측 공격 경로 봉쇄

무응답의 기본값을 "보류"로 두면 파티원이 확인을 누르지 않고 공짜로 이용할 수 있다. 따라서 **보류는 결제와 이용을 동시에 멈춘다.**

```
무응답 발생
  → 당월 결제 미집행 (파티원 보호)
  → 동시에 해당 슬롯 이용 중단 안내 + 자격증명 열람 차단 (방장 보호)
  → 7일 내 미해결 → 슬롯 회수 + 대체 파티원 모집 큐 등록
  → 3주기 연속 무응답 → 계정 신뢰도 하락, 파티 참여 제한
```

**결제도 안 되고 이용도 안 된다.** 이 대칭이 게이트를 악용 불가능하게 만든다.

### 3.4 보완 신호 — 수동 확인에만 의존하지 않는다

사용자 확인 버튼은 유일한 신호여서는 안 된다(피로도, 거짓 응답). 다음을 병행한다.

| 신호 | 구현 | 탐지 대상 |
|---|---|---|
| 파티원 확인 응답 | 앱 내 1탭 | 포괄적 이상 |
| 자격증명 열람 로그 | 앱 내 조회 이벤트 기록 | 장기 미열람 = 이탈 징후 |
| 로그인 실패 자발 신고 | 앱 내 "로그인 안 됨" 버튼 | 비밀번호 변경 |
| 방장 요금제 유지 자기확인 | 주기별 1탭 | 요금제 강등 |

> ⚠️ **한계 고지.** 구독모아는 OTT 계정을 직접 조회할 수 없다(실사 보고서 §3-5). 위 신호는 **전부 간접 신호이며, 거짓 응답을 탐지할 수 없다.** 게이트의 가치는 "사기를 탐지한다"가 아니라 **"사기당할 금액을 1개월분으로 묶는다"(INV-3)**에 있다. 이 구분을 투자자·사용자 커뮤니케이션에서 흐리지 않는다.

### 4.3 네이버플러스를 "조건부"로 두는 이유

G1·G2를 통과하지만 **파티원의 지불 근거가 약하다.**

- 방장은 **3명을 무료로 초대**할 수 있다 → 분담금을 받을 명분 자체가 희박하다
- 적립 혜택이 **구성원 합계 20만원 한도를 공유**한다 → 인원이 늘면 1인당 혜택이 희석된다
- 디지털 콘텐츠 무료 이용은 **패밀리 대표 1명에게만** 제공된다

즉 "4명이 4,900원을 나눠 낸다"는 산술은 성립하지만, **파티원이 받는 가치가 분담금 1,225원 + 수수료 290원에 미치는지가 불확실하다.** Phase 1에서 실제 전환율로 검증할 대상이며, 가치 제안이 확인되지 않으면 종목에서 제외한다.

### 4.4 재선별이 남긴 결론

> **G1 ∩ G2를 완전히 통과하는 종목은 Duolingo 1개, 조건부 포함 2개다.**
>
> 활성 유료 파티원 BEP는 최소 조직(4명) 기준 **7.0만 명**이다(`appendix-bep-benchmark.md`). **2개 종목으로 7만 명을 모으는 것은 현실적이지 않다.**
>
> 따라서 **파티 매칭은 수익 사업으로 성립하지 않는다.** v2.1은 이를 폐기하지 않고 **고객 획득 채널로 재배치**한다(§5.1, §10). 피클플러스가 영업이익률 19.3%를 내는 것은 Tier C(넷플릭스)를 하기 때문이며, 분담금이 큰 시장은 그곳뿐이다. 합법과 경제성의 교집합은 좁다 — 이 사실을 전략으로 받아들이는 것이 v2.1이다.

### 4.5 운영 요구사항

- 서비스별 **약관 원문·검토일·판정 근거·G1/G2 통과 여부**를 레지스트리로 관리
- **약관 변경 모니터링을 월 1회 정기 업무로 편성.** 가격 인상은 G2를 개선하고, 가격 인하·인원 확대는 G2를 악화시킨다 — **양방향 모두 추적**
- **멜론·지니 가족 요금제 신설은 모니터링 트리거다.** 음원 플랫폼은 이용자 기반이 크고, 신설 시 요금 구조에 따라 G1·G2를 동시에 통과할 수 있다
- 티어 하향 시 신규 파티 생성을 즉시 차단, 기존 파티는 만기까지 유지 (소급 중단 금지 — 소비자 피해 및 환불 분쟁 방지)

## 5. 수익 모델 및 유닛 이코노믹스 — v2.1 재구성

### 5.1 역할 분리 — 무엇이 수익을 내고 무엇이 고객을 데려오는가

v2.0의 오류는 **파티 매칭에 수익 책임을 지운 것**이다. §4.4에 따라 역할을 분리한다.

| 기능 | 역할 | 고정비 분담 |
|---|---|---|
| **지출 관리 프리미엄** | **수익원 (주)** | ✅ 담당 |
| **제휴 (카드 CPA·공식 프로모션)** | **수익원 (주)** | ✅ 담당 |
| **파티 매칭** | **고객 획득 채널** | ❌ 안 함 (기여이익 양수만 요구) |

### 5.2 가격표

| 대상 | 항목 | 금액 | v2.0 → v2.1 |
|---|---|---|---|
| 파티원 | 월 중개 수수료 | **₩290** | 690 → **290** |
| 방장 | 수수료 | **₩0 (무료)** | 유지 |
| 전체 | 지출 관리 프리미엄 | 월 ₩1,900 / 연 ₩19,000 | 유지 |
| 제휴 | 카드 발급 CPA, 공식 프로모션 어필리에이트 | 건당 수천~수만원 | 유지 |

**수수료를 690원에서 290원으로 내리는 이유:** Tier A 종목의 분담금이 작아(네이버플러스 1,225원) 690원은 분담금의 56%가 된다. **수수료가 상품값의 절반을 넘으면 팔리지 않는다.** 290원은 네이버플러스 기준 24%, Duolingo 기준 12%로 수용 범위에 들어간다.

**0원이 아니라 290원인 이유:** ① 무료는 허수 파티·어뷰징을 유발한다 ② 290원이면 기여이익이 양수로 유지된다(§5.3) ③ 유료 결제 경험 자체가 프리미엄 전환의 선행 지표가 된다.

### 5.3 파티 매칭 — 회원 1인 월 기여이익

| 항목 | 계산 | 금액 |
|---|---|---|
| 수익: 중개 수수료 | | **+290** |
| PG 수수료 (거래 B) | 290 × 3.52% | -10 |
| 알림톡 | 3건 × 8원 | -24 |
| 사고 충당 | 1개월 분담금 2,400 × 먹튀율 1% | -24 |
| CS | 월 티켓률 3% × 건당 3,125원 | -94 |
| **월 기여이익** | | **🟢 +138** |

하위몰 분할정산 수수료(건당 약 100원)는 분담금 거래(거래 A)에 붙어 **방장 정산액에서 차감**되므로 구독모아 손익에 들어오지 않는다(§2.4).

> **파티 매칭은 고정비를 분담하지 않는다. 적자만 아니면 된다.** +138원은 그 조건을 만족한다.

### 5.4 거래 고정비 법칙 — v2.1의 핵심 제약

**이것이 종목 선정을 지배하는 단일 법칙이다.**

거래당 비마진 고정비는 **분담금 크기와 무관하게 붙는다**: PG 10 + 알림톡 24 + 충당 24 + CS 94 ≈ **152원**(수수료 290원·분담금 2,400원 기준). 사용자가 수용하는 수수료를 분담금의 25%로 보면:

```
성립 조건 : 분담금 × 25% > 290원
최소 분담금 = 290 ÷ 0.25 = 1,160원/월
```

| 서비스 | 월 분담금 | 수용 수수료(25%) | 판정 |
|---|---|---|---|
| MS365 Family 3인 | 4,306원 | 1,076원 | ✅ (단 Tier B) |
| 넷플릭스 프리미엄 4인 | 4,250원 | 750원(공식 상한) | ✅ 경제성 / ❌ 법적 |
| Duolingo Super Family 6인 | 약 2,400원 | 600원 | ✅ |
| MS365 Family 6인 | 2,153원 | 538원 | ✅ (단 Tier B) |
| 네이버플러스 4인 | 1,225원 | 306원 | 🟡 간신히 |
| 닌텐도 패밀리 4인 | 998원 | 249원 | ❌ |
| **닌텐도 패밀리 8인** | **499원** | **125원** | ❌ **수수료 > 분담금** |

**인원을 많이 묶을수록 분담금이 작아져 경제성이 나빠진다.** 사용자에게는 8인 분할이 매력적이지만 플랫폼에는 치명적이다 — 이 역방향 인센티브가 v2.0 설계에 없었다.

### 5.5 넷플릭스를 지원하지 않는 정량적 근거 (v2.0 유지)

**가격 상한이 존재한다.** 넷플릭스 공식 추가 회원은 **월 5,000원**이다.

```
가격 상한      = 5,000원 (공식 추가 회원)
프리미엄 4인 분담금 = 17,000 ÷ 4 = 4,250원
────────────────────────────────────────
수수료 상한    = 750원
```

| 항목 | Tier A (수수료 290원) | Tier C (수수료 상한 750원) |
|---|---|---|
| CS 월 티켓률 | 3% | **20%** (월 1회 가구 Wi-Fi 인증 강제) |
| CS 비용 | 94원 | **625원** |
| PG 수수료 | 10원 | 26원 |
| 알림톡 | 24원 | 24원 |
| 사고 충당 (분담금 × 1%) | 24원 | 43원 |
| **비용 합계** | **152원** | **718원** |
| **명목 마진** | **+138원** | **+32원** |

Tier C는 마진이 32원까지 눌리며, **차지백·법무 비용·OTT 민사 리스크·PG 가맹점 해지 리스크가 전혀 반영되지 않은 숫자다.** 먹튀율이나 티켓률이 조금만 나빠지면 즉시 적자다.

보조 논거: 2025.5.9부터 넷플릭스 **광고형 스탠다드는 월 7,000원**으로 인상됐으나 **광고형 추가 회원은 월 4,000원**으로 유지됐다. 넷플릭스는 저가 합법 슬롯을 직접 공급하며 그 가격을 언제든 더 내릴 수 있다. **상한을 통제하는 주체가 경쟁자일 때 그 시장에서 마진을 설계할 수 없다.**

### 5.6 파티 매칭의 성공 지표는 매출이 아니다

파티 매칭은 CAC 기능이므로 **프리미엄 전환율로 평가한다.**

```
파티 회원 1명 연 기여이익 (수수료 290원)      : +1,656원  (+138 × 12)
프리미엄 1명 연 마진 (월 1,900원, PG·CS 차감) : +21,636원
```

**수수료 290원으로 기여이익이 양수이므로 파티 매칭은 비용 센터가 아니다.** 즉 "전환율이 획득 비용을 넘는가"를 물을 필요가 없고, 전환은 순수 추가 이익이다. 대신 판정 기준은 **"획득 채널로서 의미 있는 규모의 전환을 만드는가"**다 — 전환이 거의 없다면 기여이익 1,656원만 남는 사업이고, 그것으로는 고정비를 분담할 수 없어(§4.4 BEP 7만명) 존속 근거가 사라진다.

| 지표 | 목표 | 미달 시 |
|---|---|---|
| 파티 회원 → 프리미엄 전환율 | **≥ 5%** | 획득 채널로서의 가치 없음 → §10 Phase 3에서 폐기 검토 |
| 파티 매칭 기여이익 | **> 0** | 수수료 재조정 또는 종목 축소 |
| 월 CS 티켓률 | **≤ 3%** | Tier A 가정 붕괴 → 종목 재검토 |

- 프리미엄: 월 1,900원 (무제한 구독 등록, 지출 리포트, 가족 공유)

### 6.2 파티 생성 / 매칭 (v1 기능 4·5) — Phase 1, CAC 기능

**방장 플로우**
1. 서비스 선택 — **§4.2 G1∩G2 통과 종목만 노출** (현재 Duolingo, 네이버플러스 조건부)
2. 정원·분담금 설정 (요금제 기준 자동 계산, 상한 검증)
3. **정산 계좌 등록 + 본인확인** (PG 하위몰 온보딩)
4. 실수령액 고지 — 분담금에서 PG 수수료(약 3.5%)와 분할정산 수수료(약 100원)를 차감한 **실수령액을 금액으로 명시** (Duolingo 6인 기준 약 2,400원 → 약 2,216원)
5. **세무 고지** — §9-5
6. (선택) 오픈채팅 초대 링크 등록
7. 자격증명 등록 — 앱 내 암호화 보관, 평문 미표시

**파티원 플로우**
1. 파티 탐색 → 상세
2. **명세 표출** — 월 분담금 + 중개 수수료 290원, 1개월 단위 결제, **선납 없음** (Duolingo 6인 기준 약 2,400 + 290 = **약 2,690원**)
   - **G2 검증을 서버에서 강제**: 분담금이 1,160원 미만인 파티는 생성 자체를 차단 (§5.4)
3. **손실 한도 고지** — "사고 시 최대 노출액은 1개월 분담금입니다" (INV-3)
4. 카드 빌링키 등록 (PG 인증창, 카드번호 미보관)
5. **1주기분 즉시 결제** → 자격증명 열람 권한 부여
6. 이후 주기는 §3 게이트 통과 시에만 결제

**동시성 요구사항 (v1 oversell 결함 대응)**
- 슬롯 점유는 `UNIQUE(party_id, slot_no)` 제약 + 행 단위 락으로 보장
- **정원 판정 로직은 서버 단독.** 클라이언트는 결과만 렌더링
- 슬롯 선점 → 결제 승인 실패 시 선점 해제(TTL 10분)

### 6.3 이용 수칙 (v1 기능 3) — 성격 전환

**v1의 "서약서"는 폐기한다.** 구독모아는 방장-파티원 사적 계약의 당사자가 아니므로 이를 강제할 지위가 없고, 양식을 제공하면 약관규제법이 적용되어 "위반 시 전액 몰취" 같은 조항은 제8조(과도한 손해배상액 예정)로 무효 가능성이 높다.

**v2: 구독모아 커뮤니티 가이드라인 + 슬롯 회수 사유 명세**

| v1 서약 조항 | v2 처리 |
|---|---|
| 비밀번호 무단 변경 금지 | **PARTY_HOLD 발동 사유** (금전 제재 아님, 결제 중단) |
| 1인 1프로필 | **SLOT_HOLD 발동 사유** + 반복 시 슬롯 회수 |
| 위반 시 예치금 몰취 | **삭제** (자력집행 불가 + 약관규제법 무효 소지) |

제재는 **금전 몰취가 아니라 "다음 주기 결제 중단 + 슬롯 회수 + 신뢰도 기록"**이다. 이것은 구독모아가 실제로 집행할 수 있는 유일한 제재이며, 동시에 적법하다.

### 6.4 "에스크로 금고" (v1 기능 2) — 전면 삭제

|---|---|

| "안심 에스크로 보증 수수료" | **"중개 수수료"** |

## 7. 공급측(방장) 전략 — v1 최대 실패 지점

실사 보고서가 던진 질문: **"피클플러스(선정산 + 미모집분 100% 보장)를 쓰는 방장이 왜 구독모아로 오는가?"** v1은 답이 없었다(12개월 외상 + 보장 없음).

| 축 | 피클플러스 | 구독모아 v1 | 구독모아 v2 |
|---|---|---|---|
| 정산 시점 | 선정산 | 🔴 12개월 분할 | 월 1회 |
| 방장 자금 리스크 | 플랫폼 신용 | 🔴 12개월 무담보 채권 | **등록 PG 보유 + 우선변제권** |
| 방장 수수료 | 수취 | 수취 | **₩0** |
| 월 실수령 (넷플릭스 프리미엄 환산) | 약 12,150원 | — | **12,300원** |
| 미모집 자리 | 100% 현금 보장 | 없음 | 🟡 수수료 면제 + 모집 우선 노출 |
| 분쟁 시 지원 | 환불 중재 | 🔴 구독모아가 재판관 | **규칙 위반 파티원 즉시 슬롯 회수 + 대체 모집** |

**v2의 방장 제안은 "현금을 더 준다"가 아니라 "관리 노동과 리스크를 없애준다"다.**
- 수수료 0원 + 실수령 12,300원으로 **금전 조건은 피클플러스와 동등 이상**
- 자금 안전성은 **법적으로 한 단계 위** (§2.3)
- 미회수 리스크를 구독모아가 아니라 **게이트 구조**가 흡수

> ⚠️ **정직한 한계.** 미모집 자리 현금 보장은 INV-1과 충돌하지 않지만(자기 비용 지출이므로) **Phase 1에서는 제공하지 않는다.** 재원 없이 약속하면 v1의 "100% 보상"과 같은 실수가 된다. 수수료 면제로 시작하고, 유닛 이코노믹스가 검증된 뒤 CAC 예산 내에서 재검토한다.

## 8. 카카오 연동 명세

### 8.1 플로우 (v1 `createKakaoGroup()` 대체)

```
[방장] 카카오톡에서 오픈채팅방 직접 생성 (구독모아 개입 없음)
   ↓
[방장] 초대 링크를 파티 설정에 등록 (선택 입력)
   ↓
[서버] 정원 달성 이벤트
   ↓
[서버] 알림톡 발송 — 링크 안내. 자격증명 미포함 (INV-4)
   ↓
[파티원] 자발적 입장
```

**선택 입력으로 둔다.** 필수로 하면 방장 진입 장벽이 되고, §7의 공급측 전략과 충돌한다.

### 8.2 알림톡 템플릿 (사전 심사 대상)

| ID | 발송 시점 | 내용 | 자격증명 |
|---|---|---|---|
| `PARTY_FULL` | 정원 달성 | 파티 시작 안내 + (등록 시) 오픈채팅 링크 | ❌ |
| `VERIFY_REQ` | 매 주기 D-3 | 이용 확인 요청 + 앱 딥링크 | ❌ |
| `CYCLE_RESULT` | D-day | 결제 완료 또는 **보류 사유** 안내 | ❌ |

준비: 카카오비즈메시지 파트너 등록 → 발신프로필 → **템플릿 사전 심사**(정보성만 허용, 광고 문구 불가). **LMS 대체발송 폴백 필수** — `VERIFY_REQ` 미도달은 곧 무응답 보류로 이어져 사용자 피해가 되므로, 도달 실패를 보류 사유로 삼지 않는다.

### 8.3 금지 사항 (구현 차단)

- ❌ 오픈채팅방 프로그래밍 생성 — 카카오 공식 미제공 ("제공을 검토 중")

- ❌ 비공식 클라이언트 자동화 — 탐지 로직 변경 시 전체 파이프라인 무통보 정지
- ❌ 공지 템플릿에 자격증명 (INV-4)

### 8.4 자격증명 전달 (앱 내 전용)

- 앱 내 전용 화면, 기본 마스킹, 열람 시 생체·PIN 재인증

## 10. 단계별 로드맵 — v2.1 재배치

**v2.0과의 차이:** Phase 0이 "1단계"가 아니라 **사업의 최종 형태**다. 파티 매칭은 그 위에 얹는 획득 채널이며, 지표 미달 시 **폐기하는 것이 정상 경로**다.

| Phase | 기간 | 범위 | 차단 조건 (Gate) |
|---|---|---|---|
| **0** | M0–M3 | **지출 관리 대시보드 + 제휴 레일 + 프리미엄.** 이것이 사업의 본체 | 없음 — 즉시 착수 가능 |
| **1** | M3–M6 | **파티 매칭을 CAC 기능으로 한정 출시.** Duolingo(+네이버플러스 조건부) 2종목, 수수료 290원, 2계층 게이트, 알림톡 | **9-1 비조치의견서, 9-2, 9-3, 9-5~9-8 완료** + **Duolingo 한국 실가격 재확인(§4.2 ※)** |
| **2** | M6–M12 | §5.6 지표 달성 시: Tier B(MS365) 약관 재검토 후 확대, 대체 파티원 모집 자동화 | **프리미엄 전환율 ≥ 5%, 기여이익 > 0, CS 티켓률 ≤ 3%** |
| **3** | M12+ | 지표 달성 시: 자격증명 비노출 로그인(9-4 근본 해결) / **미달 시: 파티 매칭 폐기(sunset)** | 법무 재검토. **Tier C는 §5.5 재계산 통과 시에만 재논의** |

### 10.1 파티 매칭 폐기(Sunset) 기준 — 미리 정한다

지표를 못 넘겼을 때 "조금만 더"로 끌지 않기 위해 **철수 조건을 착수 전에 고정한다.**

| 조건 | 판정 시점 | 조치 |
|---|---|---|
| 프리미엄 전환율 < 5% | Phase 1 종료(M6) | 종목 축소 또는 폐기 검토 |
| 기여이익 ≤ 0 (3개월 연속) | 매월 | 수수료 재조정 1회 → 미개선 시 폐기 |
| G1∩G2 통과 종목 수 0개 | 상시 (§4.5 모니터링) | **즉시 신규 파티 차단**, 기존 파티 만기까지 유지 |
| Duolingo 한국 분담금 < 1,160원 | Phase 1 착수 전 | 네이버플러스 단독 → 단독이면 Phase 1 보류 |

**폐기는 실패가 아니라 설계된 분기다.** Phase 0이 독립적으로 성립하므로 파티 매칭을 접어도 사업은 남는다. v1처럼 4개 기능을 묶었다면 이 분기가 불가능했다.

### 10.2 Phase 0을 본체로 두는 이유

- 라이선스 리스크 0, 가격 상한 제약 0, OTT 플랫폼 리스크 0
- 제휴 CPA는 건당 수천~수만원으로 **파티 수수료 290원의 10~100배**
- 고정비가 가장 작다(3명 기준 2.70억) → BEP 도달 가능성이 가장 높다
- v1처럼 동시 출시하면 **가장 안전한 기능이 가장 위험한 기능의 법적 운명에 묶인다**

## 11. 데이터 모델 핵심 요구사항

v1 명세에서 추론된 구현 결함(실사 §3-3) 대응.

### 11.1 원장 — 추가 전용 복식부기

```
ledger_entry (append-only, UPDATE/DELETE 금지)
  entry_id, txn_id, idempotency_key (UNIQUE)
  debit_account, credit_account, amount
  occurred_at, recorded_at
  party_id, slot_id, cycle_no
```

- **잔액 컬럼을 두지 않는다.** 모든 금액은 원장 집계 결과다
- INV-1 검증 쿼리를 상시 운영: **타인 자금 부채 계정의 잔액은 항상 0**이어야 한다. 0이 아니면 알럿
- 일일 PG 정산 대조 작업

### 11.2 멱등성·동시성

| 대상 | 방식 |
|---|---|
| 슬롯 점유 | `UNIQUE(party_id, slot_no)` + 행 락 + TTL 10분 선점 |
| 주기 결제 | 자연키 멱등 `(slot_id, cycle_no)` — **중복 청구는 회수 불가 손실** |
| 알림톡 | `(template_id, slot_id, cycle_no)` |
| 외부 호출 | 요청 단위 idempotency key + outbox 패턴 |

### 11.3 주기 배치 신뢰성

- 상태 기계(§3.2)를 DB 상태로 영속화. 메모리 스케줄러 상태 금지
- 멀티 인스턴스 중복 실행 방지 (분산 락 또는 리더 선출)
- **월말 경계 규칙 명시** — 약정일 31일 → 해당 월 말일로 클램프
- 결제 실패 재시도 3회(24h 간격) 후 `SLOT_SUSPENDED`
- 일일 대조: `SETTLED` 합계 vs PG 정산 보고서

### 11.4 보관 금지 항목

- 카드번호·CVC (PG 빌링키 토큰만 보관)
- 타인 자금 잔액 (INV-1)
- 알림톡·로그·에러 메시지 내 OTT 자격증명 (INV-4) — **로그 마스킹 필터 필수**

### 12.1 R1에 대한 결론 — v2.0에서 한 번 더 후퇴한다

v2.0은 "넷플릭스를 버리고 Tier A로 가면 합법이면서 수익이 난다"고 했다. **재선별 결과 그 영역은 거의 비어 있었다.**

- 분담금이 큰 시장은 넷플릭스·디즈니+뿐이고, 그곳은 약관이 막는다
- 약관이 허용하는 서비스는 분담금이 작아 **거래 고정비 152원을 수수료로 덮지 못한다**
- 피클플러스의 영업이익률 19.3%는 **Tier C를 하기 때문에** 나온 숫자다. 그들도 설립 5년, 투자 7회, 직전 연도 -5.94억을 거쳐 도달했다

> **따라서 이 기획서가 약속하는 것은 다음 세 가지로 한정된다.**
> ① 대표가 전자금융거래법 위반으로 기소될 경로를 제거한다
> ② 유닛 이코노믹스가 음수인 거래를 제거한다
> ③ Phase 0이라는, 파티 매칭과 독립적으로 성립하는 사업을 남긴다
>
> **"큰 시장에서 이긴다"는 약속은 하지 않는다.** 그 시장은 합법적으로 접근할 수 없고, 접근하려면 등록 고정비 9.7억과 가격 상한 750원이 동시에 걸려 BEP가 소멸한다(`appendix-bep-benchmark.md` §3). **이 사업의 현실적 상한을 인정하는 것이 v2.1의 본질이다.**
