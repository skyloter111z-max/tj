# v3 기획서 — 기업 SaaS 지출 관리 (1인 운영 설계)

> **작성일:** 2026-10-03
> **대체 범위:** v2.1(`submoa-v2-noncustodial-spec.md`)의 B2C 방향을 보류하고 사업을 전환한다.
> **전환 근거 한 줄:** **혼자 / 저비용 / 완전 자동 / B2C** 네 제약을 동시에 만족하는 경로는 한국 제도상 없다. B2C를 버리면 나머지 셋이 전부 열린다.

---

## 0. 왜 이 방향인가

### 0.1 B2C가 막힌 지점

개인의 카드 결제내역을 자동 수집하려면 예외 없이 라이선스 또는 금융사 제휴가 필요하다.

| 경로 | 막히는 지점 |
|---|---|
| 마이데이터 API | 자본금 5억 + **금융위 허가**. 2023년부터 API 유료(업계 원가 1,293억) |
| 스크래핑 | **2022.1.5 전면 금지** |
| 오픈뱅킹 | 계좌 거래내역만 → **카드 결제 구독은 개별 식별 불가** |
| 지정대리인 / 업무위탁 | 허가는 불필요하나 **카드사·은행이 파트너로 나서야 함** |

### 0.2 B2B에서는 같은 문제가 사라진다

**기업은 자기 데이터의 주체다.** 고객사 관리자가 OAuth로 연동하면 끝이고, 금융 규제가 개입하지 않는다.

| 제약 | B2C | **B2B** |
|---|---|---|
| 혼자 가능 | ❌ 제휴 또는 자본금 필요 | ✅ |
| 완전 자동 | ❌ 라이선스 없으면 불가 | ✅ **OAuth 1회** |
| 라이선스 | 마이데이터 허가 | ✅ **불필요** |
| BEP (1인 고정비 연 3,500만 기준) | 유료 30,225명 = **MAU 100만** | ✅ **고객사 10개** |

## 1. 불변 설계 제약

> **INV-1 — 완전 자동.** 고객이 구독 정보를 제공하는 절차를 설계에 두지 않는다. 모든 인벤토리는 연동된 API에서만 생성한다.
>
> **INV-2 — 무라이선스.** 마이데이터·전자금융업·오픈뱅킹 어느 것도 필요하지 않은 범위에서만 작동한다. 고객사 자금을 보유하거나 이전하지 않는다.
>
> **INV-3 — 1인 운영 가능.** 고객사 1곳을 늘리는 데 사람 손이 필요한 작업(수동 온보딩, 데이터 정제, 리포트 작성)을 만들지 않는다.
>
> **INV-4 — 최소 권한.** 읽기 전용 스코프만 요청한다. 쓰기·삭제 권한은 어떤 기능을 위해서도 요청하지 않는다.

## 2. 데이터 수집 아키텍처 — 연동 1개로 전수 발견

### 2.1 핵심 메커니즘

**직원이 "Google로 로그인"으로 가입한 모든 SaaS는 Google Workspace에 OAuth 토큰 기록을 남긴다.** 이 토큰 목록을 읽으면 회사가 모르는 SaaS까지 전수 발견된다.

```
[고객사 관리자] Google Workspace 관리자 계정으로 OAuth 연동 (1회, 5분)
        │
        ▼  Admin SDK Directory API (읽기 전용)
   ┌────────────────────────────────────────────────────┐
   │ users.list        → 전 직원, 마지막 로그인 시각      │
   │ tokens.list       → 직원별 서드파티 앱 토큰 전수     │
   │   GET /admin/directory/v1/users/{userKey}/tokens   │
   │   scope: admin.directory.user.security             │
   │ Reports API       → 로그인·활동 감사 로그            │
   └────────────────────┬───────────────────────────────┘
                        ▼
   ┌────────────────────────────────────────────────────┐
   │ 자동 산출물                                          │
   │ ① SaaS 인벤토리   회사 계정으로 가입된 앱 전수        │
   │ ② 유령 접근       퇴사자가 아직 토큰을 보유한 앱       │
   │ ③ 미사용 추정     90일+ 미접속 직원 × 보유 앱         │
   │ ④ 중복 도구       동일 카테고리 2개 이상 (Slack+Teams)│
   │ ⑤ 권한 위험       과도한 스코프를 가진 앱             │
   └────────────────────────────────────────────────────┘
```

### 2.2 이것이 제품이 되는 이유 — 구글 콘솔이 안 주는 것

Google 관리 콘솔에도 연결된 앱 목록이 있다(보안 > 액세스 및 데이터 제어 > API 제어). 그런데 **도메인 전체 OAuth 토큰을 권한 범위까지 묶어 보여주는 통합·필터 가능한 화면은 제공하지 않는다.** 관리자는 사용자별로 들어가 확인해야 한다.

즉 **데이터는 이미 고객사 안에 있는데 볼 수 있는 형태가 아니다.** 제품이 메우는 틈이 바로 여기다. 데이터를 새로 만드는 것이 아니라 **집계·분류·금액 환산**이 가치다.

### 2.3 요금 환산 (INV-1 유지)

OAuth 토큰에는 금액 정보가 없다. 금액은 두 단계로 자동 산출한다.

| 단계 | 방식 | 정확도 |
|---|---|---|
| **1차 (연동 즉시)** | 앱별 **공시 요금 DB** × 토큰 보유 인원 | 추정 |
| **2차 (앱별 연동 시)** | 각 SaaS Admin API에서 **실제 플랜·시트 수** 조회 | 정확 |

2차 연동 대상(Phase 2): Slack, Notion, Figma, GitHub, Atlassian, Zoom, Dropbox — 모두 Admin API로 시트 수와 플랜을 읽을 수 있다. **금액도 자동으로만 채운다.**

### 2.4 Microsoft 365 고객사 (Phase 2)

Google Workspace를 쓰지 않는 고객사는 **Microsoft Graph API + Entra ID의 enterprise applications**로 동일 구조를 구현한다. 설계가 대칭이므로 추가 비용이 작다.

## 3. 제품 범위 (MVP)

### 3.1 MVP에 넣는 것

| # | 기능 | 산출 | 근거 |
|---|---|---|---|
| 1 | **SaaS 인벤토리** | 회사 계정으로 가입된 앱 전수 + 보유 인원 | 중견기업 평균 **275개 앱**, 그중 **1/3이 Shadow IT** |
| 2 | **낭비 리포트** | 90일+ 미접속 직원이 점유한 시트의 추정 금액 | **44%의 라이선스가 미사용/미활용** |
| 3 | **유령 접근 탐지** | 퇴사자가 아직 토큰을 보유한 앱 목록 | 토큰은 퇴사 후에도 무기한 유효 |
| 4 | **중복 도구 탐지** | 동일 카테고리 중복 (Slack+Teams, Notion+Confluence) | — |
| 5 | **월 리포트 자동 발송** | 변화분만 요약한 메일 | INV-3 (사람 손 불필요) |

### 3.2 MVP에서 빼는 것

- 계약 협상 대행 (Vendr의 본업 — 사람이 하는 일, INV-3 위반)
- 결제·카드 발급 (Cledara 모델 — 전자금융 규제 진입, INV-2 위반)
- 자동 해지·시트 회수 (쓰기 권한 필요, INV-4 위반)
- 승인 워크플로우 (Phase 3)

**MVP는 "읽고 보여주는 것"까지다.** 실행은 고객사가 한다. 이 경계가 INV-2·3·4를 동시에 지킨다.

### 3.3 첫 화면이 전달해야 하는 단 한 문장

> "귀사는 **{N}개** SaaS에 월 **{금액}원**을 쓰고 있고, 그중 **{금액}원**이 90일 이상 아무도 쓰지 않는 계정입니다. 그리고 IT가 모르는 앱이 **{M}개** 있습니다."

연동 5분 뒤 이 문장이 나오면 제품은 설명이 필요 없다. **데모가 곧 영업이다** (§6).

## 4. 수익 모델

### 4.1 가격

해외 미드마켓은 연 $30K~150K(Vendr $36K~120K, Zylo $50K~150K, Torii $30K~80K+)지만, **한국 SMB 타깃은 Cledara 가격대($75~500/월)를 기준으로 잡는다.**

| 플랜 | 대상 | 월 | 연 |
|---|---|---|---|
| **Starter** | 직원 50명 이하 | ₩99,000 | ₩1,188,000 |
| **Growth** | 직원 51~200명 | ₩290,000 | ₩3,480,000 |
| **Scale** | 직원 201~500명 | ₩590,000 | ₩7,080,000 |

**가격 정당화는 절감액이다.** 직원 100명·SaaS 월 500만원 쓰는 회사에서 미사용 44%면 월 220만원이다. 월 29만원은 그 13%다.

### 4.2 손익분기

| 고정비 | Starter | **Growth** | Scale |
|---|---|---|---|
| 1인 무급 (서버·등록·기장 연 500만) | 4.2개사 | **1.4개사** | 0.7개사 |
| 1인 + 생활비 월 250만 (연 3,500만) | 29.5개사 | **10.1개사** | 4.9개사 |
| 1인 + 연 1억 목표 | 84.2개사 | **28.7개사** | 14.1개사 |

| 고객사 (Growth) | 연 매출 | 월 |
|---|---|---|
| 5개사 | 1,740만원 | 145만원 |
| **10개사** | **3,480만원** | **290만원** |
| 20개사 | 6,960만원 | 580만원 |
| 30개사 | 1.04억원 | 870만원 |

> **고객사 10개면 1인 생활이 된다.** 같은 고정비에서 B2C 구독관리는 유료 30,225명(MAU 100만)이 필요했다.

### 4.3 한계비용

| 항목 | 고객사당 월 |
|---|---|
| 서버·API 호출 | 수천원 |
| 메일 발송 | 수백원 |
| **결제 PG 수수료** | 290,000 × 3.52% ≈ **10,208원** |

**고객사당 월 기여이익이 27만원을 넘는다.** B2C에서 138원을 다투던 구조와 자릿수가 다르다. 이것이 단가가 큰 시장의 의미다.

## 5. 경쟁

| 구분 | 플레이어 | 위치 |
|---|---|---|
| **국내 직접** | **파이브클라우드** | 기업용 SW 구독 관리 + **리셀 할인(30여종 최대 40%)**. 본업은 리셀이고 관리는 부가 기능 |
| 국내 인접 | 스팬딧 | 경비·영수증 관리. SaaS 인벤토리는 아님 |
| 해외 | Vendr(2026.6 Vertice 인수), Zylo, Torii, Cledara, Sastrify | 한국 미드마켓·SMB 미진입 |

### 5.1 차별 지점

- **파이브클라우드와는 수익원이 다르다.** 그들은 리셀 마진이므로 **자기가 파는 30여종만** 관심 대상이다. 고객사가 쓰는 275개 전수를 발견하면 자기 리셀 품목 외 낭비까지 드러나는데, 그건 그들의 사업 동기가 아니다. **전수 발견은 중립 사업자만 할 수 있다.**
- **해외 솔루션은 한국 SMB 가격대가 아니다.** 연 $30K(약 4,300만원)는 직원 100명 회사가 쓸 금액이 아니다.
- 국내 B2B SaaS 시장은 "태동기·블루오션"으로 평가된다.

### 5.2 솔직한 경쟁 리스크

파이브클라우드가 전수 발견 기능을 붙이면 **리셀 마진으로 관리 기능을 무료 제공**할 수 있다. 가격 경쟁이 불가능한 구조다. 이에 대한 방어는 §9 R3.

## 6. 1인 운영 가능성 — INV-3 검증

이 사업이 성립하려면 **영업·온보딩·CS가 모두 사람 손 없이 돌아야 한다.**

| 활동 | 1인 운영 설계 |
|---|---|
| **영업** | §3.3의 문장이 영업이다. 무료 진단(연동 5분 → 리포트) → 절감액 제시 → 유료 전환. 데모를 사람이 할 필요가 없음 |
| **온보딩** | OAuth 1회. 고객사 IT 관리자가 직접. **설치·세팅 작업 없음** |
| **운영** | 월 리포트 자동 발송. 데이터 정제 불필요(API가 정형 데이터를 줌) |
| **CS** | 고객사 10~30개 규모에서 월 수 건. 1인 처리 가능 |
| **영업 리드** | 초기엔 직접 접촉 필요 — **여기가 유일한 사람 병목** (§9 R1) |

**고객사 30개까지는 1인으로 가능하다고 본다.** 그 이상은 영업 인력이 필요하고, 그때는 매출 1억이므로 채용 가능하다.

## 7. 법무·컴플라이언스

B2C 대비 극적으로 단순하다.

| # | 항목 | 조치 |
|---|---|---|
| 1 | 사업자등록 | 세무서. **전자금융업·마이데이터 모두 불필요** (INV-2) |
| 2 | **개인정보 처리 지위** | 고객사가 **처리자(controller)**, 당사가 **수탁자(processor)**. 위탁 계약서 필수. 직원 이름·이메일·로그인 시각을 다루므로 가볍지 않음 |
| 3 | Google OAuth 심사 | `admin.directory.user.security`는 **민감 스코프** → Google 앱 검증(보안 평가 포함) 필요. **일정·비용을 MVP 계획에 반영할 것** |
| 4 | 데이터 최소화 | 토큰 값 자체를 저장하지 않음. 앱 식별자·보유 인원·시각만 보관 |
| 5 | 읽기 전용 | 쓰기 스코프 미요청 (INV-4) → 사고 시 피해 범위 제한 |
| 6 | 국외 이전 | 서버를 국내 리전에 두어 국외 이전 고지 부담 회피 |

**3번이 MVP의 실질 차단 조건이다.** Google의 민감 스코프 검증은 통과까지 수주~수개월이 걸릴 수 있다.

## 8. 로드맵

| Phase | 범위 | 차단 조건 |
|---|---|---|
| **0** (M0–M1) | Google Workspace 연동 + §3.1의 1·2·3번. **무료 진단 도구로 배포** | Google OAuth 검증 신청 착수 |
| **1** (M1–M3) | 유료화(§4.1), 중복 탐지, 월 리포트 자동화 | **Google 검증 통과** |
| **2** (M3–M6) | 개별 SaaS Admin API 연동(정확한 시트·플랜), Microsoft 365 대응 | 유료 고객사 5개 |
| **3** (M6+) | 승인 워크플로우, 갱신일 알림, 벤치마크 리포트 | 유료 고객사 20개 |

**Phase 0을 무료로 배포하는 이유:** 진단 리포트 자체가 영업 자료다(§6). 그리고 무료 사용자의 인벤토리 데이터가 **앱별 공시 요금 DB와 카테고리 분류를 정교화**한다 — 고객이 늘수록 2차 정확도가 올라간다.

| R3 | 파이브클라우드가 리셀 마진으로 관리 기능을 무료화 | 🟡 중간 | 중립성(전수 발견)과 Microsoft 365 커버리지로 차별. 가격 경쟁은 하지 않음 |
| R4 | Google Workspace를 안 쓰는 고객사는 Phase 2까지 커버 불가 | 🟡 중간 | 초기 타깃을 Google Workspace 사용 기업으로 한정 |
| R5 | OAuth 토큰 기반 탐지는 **"Google로 로그인"을 쓰지 않은 SaaS를 놓친다** (이메일+비밀번호로 가입한 앱) | 🟡 중간 | 커버리지 한계를 고객에게 명시. Phase 2 개별 연동으로 보완 |
| R6 | 수탁자 지위에서 직원 개인정보를 다룸 → 사고 시 책임 | 🟡 중간 | 데이터 최소화(§7-4) + 읽기 전용(§7-5) + 위탁 계약서 |

### 9.1 R5를 과소평가하지 않는다

이 설계의 커버리지는 **"Google로 로그인"을 쓴 SaaS에 한정**된다. 이메일·비밀번호로 가입한 앱은 토큰 기록을 남기지 않는다. 다행히 B2B SaaS는 SSO 가입 비율이 높지만, **"전수 발견"이라는 표현을 마케팅에 쓸 때 이 한계를 함께 적어야 한다.** 과장하면 첫 고객사에서 신뢰를 잃는다.

### 9.2 솔직한 종합 판정

| 항목 | 평가 |
|---|---|
| 문제의 실재성 | ✅ 44% 미사용, 56%가 IT 외부 구매 — 검증된 실측 |
| 기술 실현성 | ✅ Admin SDK로 구현 가능. 연동 1개로 작동 |
| 유닛 이코노믹스 | ✅ 고객사당 월 기여이익 27만원+ |
| BEP | ✅ **고객사 10개** |
| 라이선스 | ✅ 불필요 |
| 1인 운영 | 🟡 고객사 30개까지 가능, **영업 리드가 병목** |
| 경쟁 | 🟡 국내 1곳(파이브클라우드), 해외는 가격대 상이 |

> **이 기획서의 약속:** B2C에서 막혔던 네 가지(라이선스, 단가, 가격 상한, 경쟁자 무료 제공)가 **동시에 해소된다.** 남은 과제는 단 하나 — **첫 10개 고객사를 어떻게 만나는가**다. 그것은 제도나 산술의 문제가 아니라 실행의 문제이고, 앞선 네 문제와 달리 **노력으로 풀 수 있는 종류**다.
