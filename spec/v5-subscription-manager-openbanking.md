# v5 기획서 — 구독관리 앱 (오픈뱅킹 연동 / 연 1,200원 / 1인 운영)

> **작성일:** 2026-10-03
> **범위:** 일반 소비자용 구독 지출 관리 앱. **연동은 오픈뱅킹, 가격은 연 1,200원, 운영은 1인.** N빵 매칭·B2B는 이 문서에 없다.
> **승계 없음:** v2.1~v4는 보류. 이 문서는 처음부터 다시 쓴 것이다.

---

## 0. 연동 방식 — 흔한 오해부터 정정

**카드사 앱에서 끌어오는 방식이 아니다.** 그것은 스크래핑이고 **2022년 1월 5일부터 금지**됐다. 오픈뱅킹은 **서버 대 서버**다.

```
[사용자]  구독모아 앱 → "내 카드·계좌 연결" 1회 탭
             │
             ▼
   오픈뱅킹 인증 페이지 (금융결제원)
   · 휴대폰 본인인증
   · ARS 동의
             │
             ▼
   Access Token + 핀테크이용번호(fintech_use_num) 발급
             │
             ▼
[구독모아 서버] ──── API 호출 ────▶ [금융결제원] ──▶ [카드사·은행]
   (사용자 개입 없음, 월 1회 배치)
```

| 오해 | 사실 |
|---|---|
| 카드사 앱이 로그인돼 있어야 한다 | **무관.** 설치돼 있지 않아도 된다 |
| 폰에서 알림·화면을 읽는다 | **아니다.** 서버가 금융결제원 API를 호출한다 |
| 사용자가 매번 뭘 해야 한다 | **1회 본인인증·동의 후 끝.** 이후 전자동 |

**사용자 작업은 최초 1회, 1~2분이다.** 그 뒤로는 사용자가 아무것도 하지 않는다.

**진입 자격:** 금융결제원 **이용계약 + 이용승인**을 받은 핀테크사업자. **마이데이터 허가(자본금 5억 + 금융위 허가)가 아니다.** 보안심사가 있다.

## 1. ⚠️ 사업의 단일 전제 — 먼저 확인해야 하는 것

오픈뱅킹 카드 API는 4개다.

| API | 확인 상태 | 응답 내용 |
|---|---|---|
| 카드목록조회 | 존재 확인 | 보유 카드 목록 |
| 카드기본정보조회 | 존재 확인 | 카드 기본 정보 |
| **카드청구기본정보조회** | ✅ **명세 확인** | **월별 청구 총액만.** `charge_month`, `charge_amt`, `settlement_day`, `settlement_date`, `card_id` — **가맹점명·개별 건 없음** |
| **카드청구상세정보조회** | 🔴 **미확인** | 명세 비공개(개발자 사이트 로그인 필요). **개별 가맹점 건을 주는지 불명** |

> **이 한 줄이 사업의 전부다.**
> `카드청구상세정보조회`가 **가맹점명 + 금액 + 승인일자를 건별로** 주면 → 카드 결제 구독을 자동 식별할 수 있고 제품이 성립한다.
> **월 청구 총액만 주면** → 카드 구독을 식별할 수 없고, 아래 경로 B로 축소된다.

### 1.1 경로 분기

| | **경로 A** (상세가 건별 제공) | **경로 B** (총액만 제공) |
|---|---|---|
| 카드 결제 구독 (넷플릭스·ChatGPT 등) | ✅ 자동 식별 | ❌ 불가 |
| 계좌 자동이체 구독 (통신비·보험 등) | ✅ | ✅ (§2.2) |
| 제품 완성도 | **완전** | **반쪽** |
| 판단 | 진행 | **사업 재검토** |

**OTT·AI 구독은 대부분 카드 결제다.** 경로 B면 핵심 종목을 전부 놓치므로 제품이 성립하지 않는다.

### 1.2 확인 방법 (Phase 0의 첫 작업, 비용 0)

1. `developers.kftc.or.kr` 개발자 계정 생성 (무료)
2. `카드청구상세정보조회` 응답 메시지 명세 열람
3. 응답에 **가맹점명 또는 거래내용 필드 + 건별 금액 + 승인일자**가 있는지 확인
4. 없으면 금융결제원에 직접 문의 (카드사별 제공 범위가 다를 수 있음)

**이것을 하기 전에는 어떤 개발도 시작하지 않는다.**

## 2. 데이터 설계

### 2.1 경로 A — 카드 결제 구독 식별 (주 경로)

```
월 1회 배치
  ├ 카드목록조회           → 사용자 보유 카드 N장
  └ 카드청구상세정보조회    → 카드별 건별 결제 내역
         │
         ▼  정기결제 판정 엔진
  ┌──────────────────────────────────────────────┐
  │ 규칙 1  동일 가맹점이 3개월 연속 등장         │
  │ 규칙 2  금액이 동일하거나 ±5% 이내            │
  │ 규칙 3  결제일 간격이 28~32일 (또는 연 1회)   │
  │ 규칙 4  가맹점명 패턴 매칭 (사전 DB)          │
  └──────────────────────────────────────────────┘
         ▼
  구독 인벤토리 (서비스명·금액·주기·다음 결제일)
```

**가맹점명 정규화 사전(DB)이 핵심 자산이다.** 카드 명세의 가맹점명은 `NETFLIX.COM`, `넷플릭스`, `PADDLE.NET* OPENAI` 등으로 지저분하게 들어온다. 이것을 정규화된 서비스로 매핑하는 사전을 운영한다. **사용자가 늘수록 미분류 가맹점 패턴이 쌓여 사전이 정교해진다** — 이것이 유일한 축적 자산이다.

### 2.2 경로 B — 계좌 자동이체 (보조)

계좌 `거래내역조회` API는 **건별로 제공**된다 (명세 확인됨).

| 필드 | 내용 |
|---|---|
| `tran_date` / `tran_time` | 거래 일시 |
| `inout_type` | 입출금 구분 |
| **`printed_content`** | **통장인자내용** — 실무상 여기에 서비스명이 찍힌다 |
| `tran_amt` | 거래 금액 |

페이지당 최대 25건. **가맹점명 필드가 아니라 통장인자내용**이므로 정규화 난이도가 더 높다.

### 2.3 완전 자동 유지

| 데이터 | 출처 |
|---|---|
| 서비스 식별 | 가맹점명 정규화 사전 |
| 금액 | 결제 내역 실측값 |
| 주기·다음 결제일 | 결제 간격 계산 |
| 요금제 변경·가격 인상 | 전월 대비 금액 변동 감지 |

**사용자에게 아무것도 요구하지 않는다.** 최초 인증 1회가 전부다.

## 3. 수익 모델 — 연 1,200원이 성립하는 이유

### 3.1 핵심: 조회 빈도가 비용을 결정한다

오픈뱅킹 조회 수수료는 2021년에 **3분의 1로 인하**됐다.

| API | 인하 전 | 인하 후 |
|---|---|---|
| 잔액조회 | 10원 | **3원** |
| 거래내역조회 | 30원 | **10원** |

**구독 관리는 실시간이 필요 없다.** 월 1회 조회로 지출 집계·D-Day 알림·가격 인상 감지가 모두 된다. **이 설계가 연 1,200원을 가능하게 한다.**

### 3.2 사용자당 연 손익

| 항목 | 카드 1장 | 카드 2장 | 카드 3장 |
|---|---|---|---|
| 수익 (연 1,200원) | +1,200 | +1,200 | +1,200 |
| PG 수수료 (3.52%) | -42 | -42 | -42 |
| 오픈뱅킹 조회 (월 1회 × 12 × 10원) | -120 | -240 | -360 |
| **연 마진** | **+1,038** | **+918** | **+798** |
| **수익률** | **86.5%** | 76.5% | 66.5% |

조회를 분기 1회로 낮추면 카드 1장 기준 마진 **1,118원(93%)**. 다만 D-Day 알림 품질이 떨어지므로 **월 1회를 기본**으로 한다.

> **연 1,200원의 수익률은 문제가 아니다. 86.5%다.** 문제는 절대액이므로 고정비를 낮추고 사용자 수를 늘리는 것이 전부다.

### 3.3 손익분기

| 고정비 | 연 | BEP 유료회원 |
|---|---|---|
| **1인 무급** (서버 80만 + 앱등록 13만 + 기장 100만 + 도메인·푸시 50만) | 243만 | **2,341명** |
| 1인 + 생활비 월 250만 | 3,243만 | 31,243명 |
| 1인 + 연 1억 | 1억 | 96,339명 |

**1인 무급으로 2,341명이면 흑자다.** 이것이 연 1,200원 모델의 현실적 목표다.

| 유료회원 | 연 수익 (마진 1,038원) |
|---|---|
| 3,000명 | 311만원 |
| 10,000명 | 1,038만원 |
| 30,000명 | 3,114만원 |
| 100,000명 | 1.04억원 |

### 3.4 비용을 사용자 수에 비례하지 않게 만드는 규칙

연 1,200원 모델은 **사용자당 변동비가 1,038원을 넘는 순간 죽는다.** 따라서:

| 규칙 | 이유 |
|---|---|
| 조회는 **월 1회 배치**. 사용자가 당길 수 있는 새로고침 버튼을 두지 않는다 | 조회 1건 = 10원. 임의 호출을 허용하면 비용이 통제 불가 |
| 카드 등록 수에 **상한(3장)** | 4장이면 마진 678원까지 떨어진다 |
| **CS 티켓을 만들지 않는 설계** | CS 1건(3,125원) = **3년치 수익**. 티켓 1건이 고객 3명의 수익을 날린다 |
| 푸시·알림은 자체 발송(FCM) | 알림톡 건당 과금 회피 |

**CS가 이 모델의 유일한 치명 비용이다.** §6에서 별도로 다룬다.

## 4. 기능 범위 (MVP)

| # | 기능 | 산출 |
|---|---|---|
| 1 | **구독 인벤토리** | 자동 식별된 구독 목록 + 월/연 합계 |
| 2 | **다음 결제일 D-Day** | 결제 간격 계산 기반 |
| 3 | **가격 인상 감지** | 전월 대비 금액 변동 알림 |
| 4 | **신규 구독 감지** | 처음 등장한 정기결제 알림 ("이거 가입하셨나요?") |
| 5 | **해지 링크** | 서비스별 해지 페이지 딥링크 (사전 DB) |

**4번이 차별 지점이다.** 토스·뱅크샐러드는 고정지출을 보여주지만, **"새로 생긴 정기결제"를 알림으로 쏘지는 않는다.** 무료 체험이 유료로 전환되는 순간이 구독 낭비의 최대 발생 지점이고, 그걸 잡는 것이 이 앱의 존재 이유다.

**MVP에서 빼는 것:** 해지 대행(사람 손 필요), 자산 관리 전반(토스 영역), 예산 관리.

## 5. 경쟁

| | 토스 | 뱅크샐러드 | **v5** |
|---|---|---|---|
| 데이터 | **마이데이터** (정밀) | 마이데이터 | 오픈뱅킹 (제한적) |
| 구독 기능 | 정기결제 자동 추출 | 고정지출 리포트 + 해지 바로가기 | 구독 전용 |
| 가격 | 무료 | 무료 | **연 1,200원** |
| 수익원 | 금융상품 중개 | 보험·건강 중개 | 구독료 |

**데이터로는 이길 수 없다.** 토스는 마이데이터로 "누락이 거의 없이" 정기결제를 추출한다. v5는 오픈뱅킹이라 커버리지가 좁다.

**싸울 수 있는 축 2개:**
1. **신규 구독 전환 알림**(§4-4) — 양사가 하지 않는 기능
2. **구독 전용 UX** — 양사는 자산관리 앱이고 구독은 탭 하나다

> **솔직한 평가:** 무료 경쟁자 2곳이 더 좋은 데이터로 인접 기능을 제공하는 시장에서 연 1,200원을 받는 것이다. **연 1,200원이라는 가격 자체가 거의 유일한 방어**다 — 월 100원은 토스를 쓰는 사람도 추가로 쓸 수 있는 금액이다. 대체가 아니라 **병행**을 노린다.

## 6. CS — 이 모델의 유일한 치명 비용

**CS 1건 = 3,125원 = 고객 3명의 연 수익.** 티켓률 1%만 넘어도 구조가 깨진다.

| 예상 문의 | 자동 처리 설계 |
|---|---|
| 연동이 끊겼다 (토큰 만료) | 자동 재인증 유도 푸시. 문의 전에 해결 |
| 구독이 안 잡힌다 (미분류 가맹점) | **앱 내 "이 결제가 구독인가요?" 1탭 확인** → 사전 DB에 반영. 티켓화하지 않음 |
| 결제·환불 | 인앱결제 또는 PG 셀프 환불 플로우 |
| 카드사 미지원 | 연동 전 지원 카드사 목록 노출 |

**티켓률 목표 0.5% 이하.** 이것을 못 지키면 연 1,200원은 성립하지 않으며, 그때는 가격을 올리는 것이 유일한 선택이다(월 1,900원이면 CS 1건이 0.14년치로 떨어진다).

## 8. 로드맵

| Phase | 범위 | 차단 조건 |
|---|---|---|
| **0** (1주) | **§1.2 명세 확인.** 개발자 계정 → `카드청구상세정보조회` 응답 필드 확인 | 비용 0. **여기서 경로 B면 사업 재검토** |
| **1** (M0–M2) | 금융결제원 이용계약·보안심사 착수. 가맹점명 정규화 사전 초기 구축 | Phase 0 경로 A 확정 |
| **2** (M2–M4) | MVP: 연동 + 인벤토리 + D-Day + 신규 구독 알림. **무료 배포** | 이용승인 완료 |
| **3** (M4+) | 연 1,200원 과금 시작. 가격 인상 감지, 해지 링크 | 티켓률 ≤ 0.5% 확인 |

**Phase 2를 무료로 배포하는 이유:** 가맹점명 사전은 사용자 데이터로만 정교해진다. 과금 전에 커버리지를 올려야 "구독이 안 잡힌다"는 CS가 줄고, 그게 §6의 전제다.
