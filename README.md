# 구독모아

구독 지출을 자동으로 모아 보고, 같이 쓸 사람을 찾는 앱.

기획은 `spec/`에, 초기 적대적 실사는 `review/`에 있다.
현행 기획서는 **`spec/v5-subscription-manager-openbanking.md`** (오픈뱅킹 연동 / 연 1,200원 / 1인 운영).

## 구성

| 경로 | 역할 |
|---|---|
| `lib/merchants.ts` | 가맹점명 정규화 사전. 이 앱의 유일한 축적 자산 |
| `lib/detector.ts` | 정기결제 판정 엔진. 건별 결제 내역 → 구독 인벤토리 |
| `lib/parties.ts` | 파티 모집 (관심 등록 모델) |
| `lib/referral.ts` | 겜스고 어필리에이트 링크 + 경제적 이해관계 고지 |
| `app/page.tsx` | 내 구독 — 지출·D-Day·신규 구독·요금 인상 |
| `app/party/` | 파티 찾기 — 4인 슬롯 UI |

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # 판정 엔진 테스트
npm run typecheck
npm run build
```

## 확인된 연동 제약 (2026-10-03)

오픈뱅킹 `카드청구상세정보조회` 명세를 확인했다. **건별 거래가 온다 — 사업 전제는 통과.**
단 두 가지 조건이 붙는다.

1. **가맹점명이 마스킹된다** (`merchant_name_masked`, 예시 `"오픈**"`).
   패턴 매칭이 듣지 않으므로 **금액 지문 + 접두 2글자**로 식별한다
   (`matchMaskedMerchant`). 둘 다 맞을 때만 확정하고, 애매하면 미분류로 남긴다.
2. **호출이 2단계 체인**이다. 기본정보조회로 결제순번을 받아야 상세조회를 할 수 있고,
   1개월치에 3회가 든다. 다만 `charge_month` 증분 조회가 되므로 갱신할 때 새 달만 받는다.
   **가입 시 과거 3개월 스캔 + 이후 앱 실행 시 월 1회 상한**(휴면 사용자는 0) 정책으로
   연 12회/카드 수준이고, 카드 등록 상한은 두지 않는다.

그 외: 가족카드 이용내역 미제공(신용정보법), 청구 기준이라 신규 구독 알림이 최대 1개월 지연.
**이용계약 전 확인 항목 7가지는 §1.5에 정리했다** — 특히 월 최소 이용료 유무(C3)와
과금 단위(C4)가 사업 성립을 가른다. 자세한 내용은 `spec/v5-subscription-manager-openbanking.md`.

현재 `app/page.tsx`는 `lib/sample-data.ts`의 샘플 거래로 엔진을 돌린다.
실제 연동은 금융결제원 이용계약·보안심사가 선행된다.
